## Question

*Can a Claude Max/Pro subscription drive a custom local web app* established that the
subscription path **works** and is **not prohibited** for single-user personal use. It
also surfaced a reason to not use it that has nothing to do with permission.

This ticket decides the access path. It contradicts a constraint the map currently lists
as fixed, so resolving it means editing the map's Notes.

**The case for console API key + Messages API:**

- **`citations` is a first-party feature.** Anthropic's docs: citations "are guaranteed to
  contain valid pointers to the provided documents", and `cited_text` is extracted by the
  API rather than generated by the model. Against a hard requirement that every claim
  carry a citation over regulatory text — where a fabricated `§ 130.31` is the worst
  possible output — this is a structural guarantee versus a prompting convention.
- **`cache_control`** lets the corpus be pinned as the cached prefix with a 1h TTL. The
  Agent SDK caches automatically and gives no handle, so you cannot guarantee *what* is
  cached when the corpus is the entire cost model.
- **Determinism.** You own every request. The Agent SDK's loop decides tool calls,
  compaction, and retries on your behalf — awkward for a system whose output is evidence.
- **Cost is small and known:** ~$45/month at 30 questions/day, and Sonnet 5's $2/$10 rate
  is now permanent. If the subscription exists *only* for this, the API is cheaper than a
  $100–200/mo Max plan.
- **Published, queryable rate limits** in TPM/RPM, versus subscription limits Anthropic
  publishes no numbers for and exposes no quota API to read.

**The case for staying on the subscription:**

- **Zero marginal cost** if the subscription already exists for other work.
- **Built-in agentic file tools** (Read/Grep/Glob) come free. The retrieval design
  currently assumes them — see below.
- No new billing relationship, no key to manage.
- Policy risk is real but bounded: Anthropic promised advance notice before changing how
  subscription usage is metered.

**Decide also:** if the answer is the API key, does the subscription path survive as a
prototyping shortcut, or is it dropped entirely?

## Consequence that must be faced here, not deferred

**This partly invalidates *What artifact does the agent read*.** That ticket resolved a
**grep-then-verify** workflow — grep markdown, open the source PDF, confirm, answer — which
presumes the agent has filesystem tools. On the Messages API there are no built-in file
tools: documents are passed as `document` content blocks, and **the citations feature
supports PDFs natively with `page_location` anchors**. That path would make the markdown
conversion largely redundant and replace hand-rolled verification with API-guaranteed
spans.

What survives from that ticket regardless of this decision: `-layout` being the only usable
extraction mode, the per-document anchor-scheme finding, the TOC/body collision hazard, and
the Part 130 duplicate exclusion. What is contingent: the grep-then-verify workflow itself
and the "PDF governs on conflict" rule.

Re-open or amend that ticket as part of resolving this one.

## Answer

**Resolved 2026-08-19 by operator decision: Claude Max/Pro subscription + Claude Agent SDK.
The console API key is ruled out.** The research established the subscription path is
technically supported and permitted for single-user use; the operator, having seen the
`citations` trade-off argued in full, chose the subscription. **This is settled — do not
relitigate it in a later session.**

### What this locks

- **Access:** Max/Pro subscription OAuth via `claude setup-token` /
  `CLAUDE_CODE_OAUTH_TOKEN`. The Agent SDK spawns a `claude` CLI subprocess and inherits
  the ambient credential; there is no in-SDK auth helper to call.
- **Model:** `claude-sonnet-5`, pinned via `model:`. Default on Pro, native 1M context.
- **Marginal cost: zero.** No console billing relationship, no key to manage.
- **Available:** `effort` (`low`–`max`), streaming via `includePartialMessages`, model
  pinning, and the built-in **Read / Grep / Glob** filesystem tools.
- **Not available:** the Messages API `citations` feature and explicit `cache_control`.
  Caching is automatic and unsteerable (1h TTL is automatic on subscription within
  included usage).

### Consequences — one resolved, one sharpened

**1. *What artifact does the agent read* is no longer contingent — it is confirmed.**
That ticket's **grep-then-verify** workflow presumed the agent has filesystem tools. On the
Agent SDK it does. Everything it decided now stands unqualified: `-layout` markdown to
search, source PDF to verify, PDF governs on conflict, per-document `anchor_scheme`,
Part 130 duplicate excluded. The contingency flag on the map is lifted.

**2. Citation integrity is now entirely a design obligation.** With no API-side
`citations`, nothing structurally guarantees a cited span exists. The map's one hard
requirement is met by construction or not at all — which promotes *What must a citation
contain, and how is fabrication prevented* from an important ticket to **the** ticket. Its
anti-fabrication clause is no longer one option among several; the design must carry a
mechanical verification step, and the grep-then-verify workflow is the load-bearing
mechanism rather than a nicety.

### Accepted risks

Recorded so they are not rediscovered and re-argued:

- **Policy is in flux.** A 2026-06-15 change that would have moved Agent SDK usage off
  subscription limits was *paused, not cancelled*. Anthropic promised advance notice.
  Accepted.
- **Consumer vs Commercial Terms for the Agent SDK is unresolved** in Anthropic's
  published documentation. Accepted for single-user, local, non-commercial use.
- **Usage limits are unpublished and unqueryable.** No numeric quota, no pre-flight API;
  exhaustion surfaces only at runtime. The design should fail gracefully on a usage-limit
  error rather than assume headroom.
- **Harness overhead.** The Claude Code system prompt and tool definitions are always
  present alongside the corpus, costing tokens and adding behavioural noise. Accepted.
